# 02 — staticcheck QF1012: `WriteString(fmt.Sprintf(...))` → `fmt.Fprintf`

Follow-up to the golangci-lint pin. Date: 2026-11-19.

## What

Commit `57c3b49b1` (`apply golangci-lint --fix (staticcheck QF1012)`) rewrites
five call sites from

```go
s.WriteString(fmt.Sprintf("    %s: %d items\n", k, len(v)))
```

to

```go
fmt.Fprintf(&s, "    %s: %d items\n", k, len(v))
```

- `cmd/iam-object-store.go` — `loadAllFromObjStore`, the slow-listing log line
  (one site).
- `cmd/server_test.go` — the payload builders in `TestGetObjectLarge10MiB`,
  `TestGetObjectLarge11MiB`, `TestGetPartialObjectLarge11MiB`,
  `TestGetPartialObjectLarge10MiB` (four sites).

No other instance of the pattern remains in the tree.

## Why

The change was made to make lint pass. It does not fix a bug.

1. `8d8e53f27` pinned golangci-lint to v2.11.4. Before that, `make getdeps`
   fetched the newest release, and from v2.12.0 its `install.sh` fails the
   checksum step, so lint never got to run.
2. With the pin, lint runs to completion and reports findings.
3. `.golangci.yml` turns on `staticcheck` with `checks: [all, …]`. "all"
   includes the quickfix checks, among them **QF1012**: "Use
   `fmt.Fprintf(x, ...)` instead of `x.WriteString(fmt.Sprintf(...))`".
4. These five sites were the QF1012 findings. `golangci-lint --fix` applied the
   suggested rewrite, and that output is the commit.

## Is it correct

Yes. `strings.Builder` and `bytes.Buffer` both implement `io.Writer`, so
`fmt.Fprintf` formats directly into them. The old form built a temporary string
and then copied it in. The output is byte-for-byte the same. The rewrite saves
one allocation and one copy per call:

- in the tests, 10–11 K throwaway strings per test;
- in `iam-object-store.go`, nothing worth measuring: the line runs only when
  an IAM listing exceeds `maxIAMLoadOpTime`.

## Why not the obvious alternatives

- **Disable QF1012 in `.golangci.yml`:** keeps upstream code untouched, but
  turns off a correct check for every future change to hide five mechanical
  findings. The upstream diff stays small either way.
- **`//nolint` per site:** same objection, plus five comments that explain
  nothing.
- **Leave the findings:** lint is a CI gate (`make test` runs `verifiers`), so
  the pin would just swap one red build for another.
